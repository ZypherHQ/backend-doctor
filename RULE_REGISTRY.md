# Rule Registry

Release status: Go, Node/TypeScript, Java/Spring, security, dependency, secrets, infrastructure, API/OpenAPI, Agent Slop observable-pattern rules, bounded semantic DTO-shape fingerprints, unsupported-language coverage, safe-fix workflows, SARIF schema validation, CI gates, cache replay, and local release dry-run surfaces are verified for local release-candidate scope. Commit `ea73ebcba49a9fc0bac260bcacad961ffad0c7bb` covers `node/sql-string-concat` consuming real AnalysisFacts for request-source-to-SQL sink flows with conservative producer/consumer gates. Commit `f048a78` covers `node/child-process-shell-injection` consuming Node AnalysisFacts for local request-source-to-command sink flows with sync child-process command sinks, fallback preservation, same-line de-dupe, and conservative shell semantics. Committed Python evidence at `0a0530a7cfbf47892cc5bc98fe700b92e701c916` covers `python/sql-string-format` consuming Python AnalysisFacts for local request-source-to-SQL sink flows with strict source/sink/edge/sanitizer/range gates. Committed Go evidence at `e7e3b8a5ce98017a44955d3b800cbc4612fcb899` covers `go/sql-string-concat` consuming Go AnalysisFacts for local request-source-to-SQL sink flows, with a non-blocking follow-up for real-adapter context-sink emission/regression coverage. Committed Java evidence at `00d37cdd6d3a44fab2847b5ff6c996e4718e109b` covers `java/sql-string-concat` consuming Java AnalysisFacts for local request-source-to-SQL sink flows. Committed PHP evidence at `8ec7fda` covers `php/pdo-query-string-concat` consuming PHP AnalysisFacts for local request-source-to-SQL sink flows while preserving prepared/parameterized suppression and PHP shell-exec SQL-style exec protections. `--fix-guided` previews semantic/riskier fixes by default, with guarded temporary-copy application verified only under explicit `--fix-guided --yes`. Tier 2 Python/C#/.NET/PHP/Rust and Tier 3 Ruby/Kotlin/Scala/Elixir/C/C++ have fixture-backed first integrations and gated external-tool hooks; they are not yet production-grade all-language maturity claims.

P0 fixture completeness is enforced in rules tests: every enabled builtin rule must appear in at least one committed fixture scan. `node/dead-export` and `node/circular-import-risk` stay disabled until broader TypeScript import/symbol graph validation is ready; package exports, graph ignores, barrels, dynamic/plugin registries, and tsconfig path aliases have false-positive control tests.

## Enablement Requirements

A rule cannot be enabled by default until it has:

- stable metadata;
- explanation and remediation;
- bad and good fixtures;
- expected output snapshot;
- severity and confidence rationale;
- false-positive notes;
- suppression behavior tests;
- SARIF mapping tests.
